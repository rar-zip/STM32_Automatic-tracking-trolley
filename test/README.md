## 1. Test_1 — 通信验证

### 目标

验证 STM32 能否正确接收并解析 OpenMV 发送的二进制视觉数据帧。

### 实现

- **`main.c`** — 纯数据接收版本，小车运动代码**全部注释**
- 使用 USART1 (PA9/PA10) + DMA1 Channel5 接收
- IDLE 空闲中断触发帧解析
- 校验逻辑：帧头 `0x55 0xAA` + 校验和 + 帧尾 `0x0D`

### 数据结构

```c
#pragma pack(1)
typedef struct {
    uint8_t  head1;     // 0x55
    uint8_t  head2;     // 0xAA
    int16_t  x_err;     // X轴偏差（像素）
    int16_t  y_err;     // Y轴偏差（像素）
    uint8_t  status;    // 状态位
    uint8_t  checksum;  // 校验和
    uint8_t  tail;      // 0x0D
} OpenMV_Data_t;
```

### 调试方式

进入 Keil Debug 模式，在 `new_data_flag` 处置断点，观察 `target_data.x_err` / `target_data.y_err` 是否正确传输。

### 局限性

- 帧头查找依赖固定位置（`rx_buffer[0]`），未做动态搜索
- 未处理 ORE（溢出错误），连续帧可能丢数据
- 无运动控制，无法验证视觉反馈闭环

## 2. Test_2 — 首次运动

### 目标

在通信验证通过后，解除运动代码，让小车根据 OpenMV 视觉数据自主转向。

### 子版本说明

| 版本                             | 说明                                         |
| -------------------------------- | -------------------------------------------- |
| `TwoWheelVersion(×)`             | 两轮方案，已废弃（目录标记 ×）               |
| `FourWheelVersion/Test_TwoWheel` | 四轮方案中的两轮控制，**本次测试使用的版本** |

### Test_1 → Test_2 核心改进

#### 通信增强

- **动态帧头搜索**：不再假设帧头在 `rx_buffer[0]`，而是遍历缓冲区查找 `0x55 0xAA ... 0x0D`
- **ORE 处理**：ISR 中新增溢出错误清除，防止连续接收时锁死
- **校验和精确校验**：仅对前 7 字节（0-6）累加，而非整帧

#### 运动控制

- 引入 `extern void Set_Motor(uint8_t motor, int16_t speed)` 单轮控制
- 引入**丢线计数器** `lose_line_cnt`，连续 10 帧丢失 → 刹车
- **按键启动安全机制**：上电后等待 PA15 按键按下，才启动循迹

#### 控制策略（Bang-Bang 控制）

```
x_err >  30  → 右转：左轮 85 / 右轮 -25（原地差速）
x_err < -30  → 左转：左轮 -25 / 右轮 85
|x_err| ≤ 30 → 直行：两轮均 60
status == 0  → 丢线计数 +1，超过 10 帧停车
```

### 已知问题

- 转弯幅度**较大且不精准**，阈值固定 ±30
- 直行速度较高（60），弯道响应不够柔和
- 丢线立即降速但无记忆恢复机制

```
│   └── User/main.c      # 带运动控制的完整版本
└── TwoWheelVersion(×)/  # 废弃方案
```

## 3. Test_3 — 最终调参

### 目标

在 Test_2 的基础上精细调整运动参数，使小车循迹更加**稳定、平滑、准确**。

### Test_2 → Test_3 核心改进

代码结构与 Test_2 的 FourWheel 版本基本一致（`main.c` 内容完全对齐），此阶段重点在于**参数校准**：

- **阈值调优**：死区 x_err 阈值、丢线帧数阈值
- **速度曲线**：直行速度与转弯速度的比例关系
- **实际路径测试**：在赛道上反复测试，记录不同光照/弯道的表现

### 调参项参考

| 参数         | Test_2 值 | 说明                 |
| ------------ | --------- | -------------------- |
| 死区阈值     | ±30 px    | x_err 在此范围内直行 |
| 转弯左轮速度 | 85 / -25  | 高速差速转向         |
| 直行速度     | 60        | 两轮等速             |
| 丢线帧数上限 | 10 帧     | 超过此值刹车         |

> 具体优化后的参数值见 `final/stm32_car/User/main.c` 中的最终版 P 控制器实现。

## OpenMV 测试 — test_1.py

位于 `openmv_h7_test/test_1.py`，与 STM32 端配套的视觉追踪测试脚本。

### 核心功能

- **多阈值黑线检测**：3 组 RGB565 LAB 阈值组合，适应不同光照
- **低通滤波**：`FILTER_STRENGTH = 0.3`，平滑 x_err / y_err 输出
- **目标筛选**：
  - 宽高比：`0.2 < w/h < 5.0`
  - 密度：`> 0.2`
  - 像素阈值：`> 600`
  - ROI 裁剪：左右各留 5% 边距
- **二进制帧输出**：`0x55 0xAA x_err y_err status checksum 0x0D`
- **LED 状态指示**：绿灯闪烁 = 追踪中，红灯闪烁 = 丢失

### 丢失处理

- 超过 500ms 未检测到目标 → 发送最后一帧已知位置 + `STATUS_LOST (0x01)`
- 500ms 内短暂丢失 → 打印 "Searching..."，不发送丢失帧
